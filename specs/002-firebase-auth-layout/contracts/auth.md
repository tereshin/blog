# Contract: Вход через Firebase

Браузер ходит только на `gateway`. Cookie сессии ставит `gateway`. `identity-service` cookie браузера не видит и получает идентификатор сессии служебным заголовком, как раньше.

Поля — [data-model.md](../data-model.md). Какую учётную запись открыть по токену — [research.md](../research.md), решение 3. Нейтральный ответ регистрации и указание почты — решение 8.

## Конфигурация панели

`GET /v1/auth/config` без сессии.

| Поле | Смысл |
| --- | --- |
| api_key | Веб-ключ для окна провайдера. Это не секрет сессии. В бандл сборки не вшивается |
| auth_domain | Домен обработчика Firebase |
| project_id | Проект |
| providers | Включённые способы: `{ id }`. `password`, `google.com`, `github.com` и любой другой id проекта |
| emulator_host | Адрес эмулятора или `null`. В `prod` всегда `null` |

Только когда `emulator_host` задан, ответ дополнительно содержит `test_participants`: адреса и подписи участников seed и `test_password` для входа в один жест. В `prod` этих полей нет. Кэш списка провайдеров на сервисе — 60 секунд в памяти процесса.

Панель показывает форму почты, если в списке есть `password`, и кнопку на каждый другой id. У кнопки есть имя для читалки экрана. Неизвестный id не прячется: он открывается тем же окном, что Google и GitHub.

Ошибка загрузки конфигурации оставляет панель на месте и предлагает повторить. Раздел под панелью не меняется.

## Регистрация почтой

`POST /v1/auth/registrations`

Тело: `email`, `password`. Пароль короче 8 символов или адрес не похож на почту — отказ у поля, пользователь Firebase не создаётся, строка участника не создаётся. Этот отказ выглядит иначе, чем успех: человек ещё не отправил принятую форму.

Регистрация закрыта — один и тот же отказ `registration_closed` и для нового адреса, и для адреса, который уже есть у участника. Строка не создаётся. По ответу не видно, занят ли адрес.

Регистрация открыта — и для свободного адреса, и для адреса, который уже есть у участника, один и тот же ответ `200` с телом `{ status: 'pending' }`. Cookie сессии нет. Текст не предлагает войти и не говорит, что адрес занят.

Свободный адрес при этом создаёт пользователя Firebase и строку участника с `email_verified = false` и отправляет письмо. Занятый адрес не создаёт ни строку, ни пользователя Firebase и письмо не отправляет. Имя профиля у новой строки — часть адреса до `@`.

Сессию этот маршрут не открывает. Человек входит отдельно, затем подтверждает письмо. Сброс пароля по-прежнему не сообщает, есть ли адрес.

## Вход

`POST /v1/auth/sessions`

Тело — одно из двух:

- `method: password`, `email`, `password`. Неверный пароль и неизвестный адрес отвечают одним `invalid_credentials`. Верный пароль неподтверждённой почты открывает сессию с `email_verified = false`.
- `method: id_token`, `id_token`. Так приходит окно Google, GitHub и остальных провайдеров. Токен проверяет identity (издатель, аудитория, срок). Чужой проект и просроченный токен — отказ, строка не создаётся.

Успех ставит cookie. Отказ cookie не ставит. Регистрация cookie не ставит: сессия начинается здесь.

Закрытие окна провайдера, ошибка поставщика и обрыв до ответа сессии: панель объясняет, что вход не завершён, адрес раздела тот же, учётки площадки нет. Если площадка явно отвергла вход (`registration_closed`) и окно поставщика уже создало пользователя Firebase, identity удаляет этого пользователя, только когда его uid ни к кому не привязан. Обрыв связи после успешной записи строку не откатывает и пользователя Firebase не удаляет: повтор того же входа открывает её.

Повтор того же способа открывает ту же строку. Выход — прежний `POST /v1/auth/logout`: сервер гасит сессию, gateway снимает cookie.

`GET /v1/auth/google` и `GET /v1/auth/google/callback` больше не существуют.

## Письма

| Действие | Маршрут | Ответ |
| --- | --- | --- |
| Указать почту, пока своя не подтверждена | `POST /v1/auth/email-claims` при сессии, тело `email` | Адрес не похож на почту — отказ у поля, строка не меняется. Иначе всегда `{ status: 'pending' }`. Свободный адрес записывается, `email_verified` остаётся ложью, уходит письмо. Адрес другого участника не записывается и письмо не уходит. Экран тот же и не говорит, что адрес занят. Действия участника остаются закрытыми. Уже подтверждённую почту маршрут не меняет |
| Отправить подтверждение ещё раз | `POST /v1/auth/email-verifications` при сессии | Всегда успех, без указания, ушло ли письмо. Почты на строке ещё нет — письма нет, ответ тот же |
| Подтвердить адрес кодом из письма | `POST /v1/auth/email-verification-confirmations`, тело `oob_code` | Сессия не обязательна. Принятый код ставит `email_verified = true` строке с этим uid и сам сессию не открывает. Чужой код учётку не подтверждает и не сообщает, чья она |
| Запросить сброс пароля | `POST /v1/auth/password-resets`, тело `email` | Всегда один и тот же успех. Существует ли адрес, ответ не говорит |
| Задать новый пароль | `POST /v1/auth/password-reset-confirmations`, тело `oob_code`, `password` | Пароль короче 8 символов не сохраняется. Негодный код — отказ без сведений об учётке |

Страница действия живёт в том же каркасе, по адресу `/auth/action`. Она читает `mode` и `oob_code` из query, отправляет их на маршруты выше и не оставляет код в новом адресе после отправки.

## Кто что может, пока почта не подтверждена

Чтение публичного — можно. Выход — можно. Повтор письма — можно. Указать почту на площадке — можно, пока своя не подтверждена. `GET /v1/auth/session` отдаёт свою `email` (или `null`) и `email_verified`, чтобы панель показала форму адреса, когда поставщик подтверждённую почту не прислал.

Публикация, комментарий, реакция, подписка, закладка, сообщение и правка профиля — отказ `email_unverified` с объяснением. Ограниченный участник по-прежнему получает отказ ограничения, даже если почта подтверждена; если он и ограничен, и не подтверждён, текст — про ограничение.

Администратор без роли суперадминистратора вид реакций не меняет. Это правило настроек, не правило почты: [reactions.md](./reactions.md).

## Служебный контекст

К claims, которые gateway уже подписывает, добавляется `email_verified`. Нет поля — читатель принимает истину. Мутации участника в `content`, `discussion` и `messaging` вызывают один предикат из `packages/contracts`.

## Окружения

| | local и dev | prod |
| --- | --- | --- |
| Издатель токена | эмулятор Auth | `https://securetoken.google.com/<FIREBASE_PROJECT_ID>` |
| Контейнер | `firebase-auth` есть, `mock-google` нет | нет ни эмулятора, ни `mock-google` |
| Старт identity | нужен адрес эмулятора | падает, если эмулятор задан, издатель чужой или секрет равен `CHANGE_ME` |
| Тестовый пароль в `GET /v1/auth/config` | да | поля нет, процесс с таким полем не стартует |
| Обходной маршрут входа | нет | нет |

Переменные identity, все в `infra/env/*.env.example` заглушками: `FIREBASE_PROJECT_ID`, `FIREBASE_AUTH_DOMAIN`, `FIREBASE_WEB_API_KEY`, `FIREBASE_SERVER_API_KEY`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`, `SEED_AUTH_PASSWORD` (только local и dev), `FIREBASE_AUTH_EMULATOR_HOST` (только local и dev). Прежние `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`, `GOOGLE_ISSUER_URL` удаляются.

В `local` письма читаются из эмулятора, а не из ящика. Боевой проект оператор включает сам: почта, Google, GitHub, минимальный пароль 8, защита от перебора адресов, authorized domains на origin площадки. Этих значений в репозитории нет.

## CSP

Политика gateway и nginx остаётся без `unsafe-inline` и `unsafe-eval`. К `connect-src` добавляются `https://identitytoolkit.googleapis.com` и `https://securetoken.googleapis.com`. К `frame-src` — origin `auth_domain`, `https://accounts.google.com` и уже стоящий `https://github.com`. В local и dev к обоим спискам добавляется origin эмулятора. Произвольный `https:` не разрешается.

## Идемпотентность и журнал

Мутации этой страницы принимают `X-Idempotency-Key`. Повтор регистрации с тем же ключом не создаёт вторую строку и снова отвечает `pending`. Повтор указания почты с тем же ключом не привязывает чужой адрес. Повторный сброс пароля может отправить письмо ещё раз и всё равно не сообщает, есть ли адрес.

Тела `/v1/auth/*` в журнал не пишутся. Redact дополнительно покрывает `password`, `id_token`, `oob_code`.
