# Data Model: Вход через Firebase, вид реакций и каркас

Дельта к модели фичи 001. Неперечисленные сущности, копии и события остаются как в `specs/001-community-blog-platform/data-model.md`.

Имена полей в таблицах, JSON и событиях — `snake_case`. Новых баз и новых сервисов нет.

## Владение

| Сущность | Владелец | Куда расходится |
| --- | --- | --- |
| Участник, Способ входа, Сессия | `identity` | Снимок участника по-прежнему `identity.user.created` / `updated` / `restricted`. Имя для профиля — только в `created`. `email_verified` в эти копии не кладётся: он едет в служебном JWT |
| Вид реакции | `content` (строка настроек площадки) | `content.settings.updated` v1 получает необязательное поле. Картинку обсуждение не копирует |
| Поставленная реакция и счётчик | `discussion` | Без изменений. Смена вида строки счётчика не пишет |
| Каркас страницы | никому, это вёрстка клиента | В базе нет. Положение прокрутки ленты по-прежнему `sessionStorage` |

## Участник

Строка `users` базы `identity`. Колонка `google_sub` удаляется после переноса в способы входа.

| Поле | Правило |
| --- | --- |
| id | Внутренний ключ, как раньше |
| public_number | Публичный номер, как раньше |
| email | Пустая, пока способ входа не принёс подтверждённый адрес и человек не указал адрес на площадке. Регистрация почтой пишет адрес сразу, но `email_verified` остаётся ложью до письма. Уникальна в нижнем регистре; пустых строк может быть несколько. Одна подтверждённая почта — один участник |
| email_verified | Ложь, пока письмо площадки или подтверждённый адрес поставщика не закрыли её. Повторный подтверждённый вход чужим способом не сбрасывает уже стоящую истину. Неподтверждённый адрес из токена в это поле и в `email` не копируется |
| role | `member`, `admin`, `superadmin` |
| can_publish | Как раньше |
| restricted_at | Как раньше |
| appearance | Как раньше |
| created_at | Как раньше |

Правила перехода — таблица `decideSignIn` в [research.md](./research.md). Почта суперадминистратора из `SUPERADMIN_EMAIL` при подтверждённом адресе связывается с уже созданной командой `bootstrap-prod` строкой и получает роль `superadmin`, даже если регистрация закрыта.

Имя и аватар профиля этой таблицей не владеют. Повторный вход их не перезаписывает. Стартовое имя уезжает один раз в `identity.user.created.display_name`.

## Способ входа

Таблица `auth_identities` базы `identity`. Сам по себе участником не является.

| Поле | Правило |
| --- | --- |
| id | Внутренний ключ |
| user_id | Участник. Несколько строк на одного участника допустимы |
| firebase_uid | Уникален во всей таблице. Повторный вход тем же пользователем Firebase находит эту строку |
| provider_id | `password`, `google.com`, `github.com` или другой идентификатор, который вернул токен |
| created_at | Момент привязки |

Почта на этой строке не хранится: для склейки читается почта участника и признак подтверждения в токене. Неподтверждённый адрес чужую строку не получает.

Существующие `google_sub` переносятся сюда одной миграцией (`provider_id = google.com`) и после этого колонка снимается. Пустой `google_sub` у суперадминистратора до первого входа означает ноль строк в `auth_identities`, не отдельное состояние.

## Сессия

Без новой таблицы. `sessions(id, user_id, created_at, expires_at, revoked_at)` как в фиче 001. Выход и ограничение по-прежнему ставят `revoked_at` всем сессиям участника.

В служебный контекст и в `GET /v1/auth/session` добавляется `email_verified`. Тот же ответ сессии отдаёт свою `email` или `null`. Если в старом JWT поля `email_verified` нет, читатель считает его истиной. Новый identity пишет фактическое значение всегда.

Состояние `auth_states` (PKCE для перехода на Google) удаляется вместе с маршрутом `/v1/auth/google`: окно провайдера держит свой `state` само, сервер площадки его не хранит.

## Вид реакции

Четыре записи на одну строку настроек площадки. Новой таблицы видов нет, пятого вида нет.

| Поле | Правило |
| --- | --- |
| kind | `laugh`, `heart`, `thumb` или `fire`. Набор закрыт |
| presentation | `emoji` или `image` |
| emoji | Обязателен при `emoji`. Одна графема, и эта графема — эмодзи. Пустое и несколько графем не сохраняются |
| image_url | Обязателен при `image`. Адрес только из хранилища площадки, те же правила, что у `logo_url`. Чужой origin не сохраняется |

Значения, пока суперадминистратор не сохранял форму: эмодзи `😄`, `❤️`, `👍`, `🔥` для `laugh`, `heart`, `thumb`, `fire`.

Смена вида не меняет строк реакций, счётчиков и `my_reaction`. Непринятое сохранение оставляет предыдущие четыре записи.

Текстовое имя (`reaction.laugh` и соседние ключи) в этой настройке не хранится и этой формой не меняется.

## Каркас страницы

Не хранится. Состояние ширины — ширина окна, не пользовательская настройка.

| Зона | Когда есть | Размер |
| --- | --- | --- |
| Полоса | Окно от 1280px | 1280px по центру. Просвет между столбцами 16px, оба просвета внутри 1280. Центр — остаток, 708px |
| Шапка | Всегда | Одна строка, липнет к верху окна, высота 56px. Кнопка поиска стоит перед уведомлениями на любой ширине |
| Левый столбец | Окно от 768px | 220px, липнет под шапкой, при переполнении крутится сам |
| Центр | Всегда | На 768–1279px забирает ширину окна после левого столбца и просвета. Ниже 768px — одна колонка |
| Правый столбец | Только от 1280px | 320px, липнет под шапкой. Пустой не отдаёт ширину центру. Ниже 1280px в потоке отсутствует |

Прокрутка страницы — документ. Прокрутка переполненного столбца — сам столбец. Светлый и тёмный вид ширины не меняют.

Кнопка меню шапки есть только ниже 768px и открывает тот же левый список. Текущий пункт списка отмечен. Правый столбец доступен читалке как «Популярные комментарии», левый — как навигация.
