# Data Model: Платформа публикаций и обсуждений

Хранимые сущности площадки, снимки экранов для центра и состояние каркаса, которое живёт только в браузере.

Правила видимости одни на все выборки. Зритель видит текст только если функция доступа возвращает да. В карточку ленты, правую карточку, закладки и профиль попадает только то, что функция доступа отдала этому зрителю.

Имена полей ниже — концептуальные. В таблицах, JSON ответов `/v1/*` и событиях они пишутся в `snake_case` по правилам нейминга (`public_number`, `can_publish`, `reaction_count`); таблицы — во множественном числе (`users`, `articles`).

## Владение данными

Каждая сущность принадлежит ровно одному сервису и его базе. Чужие поля, нужные для чтения, сервис держит копией и обновляет по событиям владельца; копия никогда не пишется напрямую.

| Сущность | Владелец | Копии у других (по каким событиям) |
| --- | --- | --- |
| Участник, Сессия | `identity` | `content`: `role`, `can_publish`, `is_restricted`, `created_at` для проверки публикации и знака «Год на площадке» (`identity.user.created`, `identity.user.updated`, `identity.user.restricted`); `discussion`, `messaging`: `is_restricted` (те же события) |
| Профиль, Занятый адрес, Тема, Статья, Подписка, Продвижение, Настройки площадки, Жалоба | `content` | `discussion`: `article.visibility`, `status`, `comments_enabled`, `author_id`, `title`, `slug` (`content.article.published`/`updated`/`hidden`/`deleted`); `discussion`, `messaging`, `notification`: `display_name`, `avatar_url` автора (`content.profile.updated`) |
| Комментарий, Реакция, Просмотр, Закладка, Просмотренное в ленте, счётчики статьи и комментария, Репутация | `discussion` | `content`: `reaction_count`, `comment_count`, `view_count`, `bookmark_count` на статье (`discussion.article_counters.updated`); `reputation` на профиле (`discussion.reputation.updated`) |
| Диалог, Сообщение | `messaging` | — |
| Уведомление | `notification` | — (создаётся по событиям `discussion.comment.created`, `discussion.reaction.added`, `messaging.message.sent`, `content.article.hidden`) |
| Файл | `media` | адрес файла хранится в блоках статьи и профиле как строка, без ссылки на таблицу |

Общие таблицы инфраструктуры в каждом сервисе: `outbox(event_id, name, payload, occurred_at, published_at)` и `processed_events(event_id, processed_at)`. В сервисах с данными seed добавляется `seed_runs(profile, anchor_at, started_at, finished_at)` — см. [Тестовые данные](#тестовые-данные-seed).

Сессия — строка `identity`: `id`, `user_id`, `created_at`, `expires_at`, `revoked_at`. Выход и ограничение участника ставят `revoked_at` всем его строкам и публикуют `identity.session.revoked`.

## Участник

Учётная запись после входа через Google.

| Поле | Правило |
| --- | --- |
| id | Внутренний ключ |
| publicNumber | Публичный номер. Адрес профиля, если короткий адрес не задан |
| googleSub | Уникальный идентификатор Google. Повторный вход находит эту строку. Пусто только у суперадминистратора, созданного командой `bootstrap-prod`, до его первого входа: вход с подтверждённой назначенной почтой записывает сюда `sub` |
| email | Почта Google на момент входа |
| role | `member`, `admin` или `superadmin` |
| canPublish | Право создать и опубликовать статью |
| restrictedAt | Пусто, если человек не ограничен. Иначе момент ограничения |
| appearance | `light` или `dark`. Пустое значение трактуется как тёмный вид, пока человек сам не выбрал |
| createdAt | Момент появления на площадке. Год на профиле и знак «Год на площадке» берутся отсюда |

Правила:

- Первый вход назначенной почты суперадминистратора создаёт роль `superadmin` даже при закрытой регистрации.
- Другая новая учётка при закрытой регистрации не создаётся.
- Ограниченный может войти. Публикация, комментарий, реакция, подписка, закладка и сообщение для него отклоняются.
- Администратор модерирует статьи и комментарии и не меняет настройки площадки, темы и состав администраторов.
- Выход не удаляет строку. Следующий запрос идёт как гость.

## Профиль

Один к одному с участником.

| Поле | Правило |
| --- | --- |
| userId | Участник |
| displayName | От 1 до 50 символов. Без имени профиль не сохраняется |
| bio | До 500 символов или пусто |
| avatarUrl | Адрес аватара или пусто |
| coverUrl | Адрес обложки или пусто |
| slug | Короткий адрес или пусто. Если пусто, публичный путь — `publicNumber` |
| reputation | Копия из `discussion.reputation.updated`. На экране не меньше нуля |

Чужой посетитель видит имя, описание, аватар, обложку и только те статьи, которые сам может читать. Числа «N подписчиков» и «N подписок» — числа строк Подписки.

## Занятый адрес

Один реестр на профили, темы и статьи.

| Поле | Правило |
| --- | --- |
| slug | 3–40: `a–z`, цифры, дефис, не с края дефисом |
| ownerType | `profile`, `topic` или `article` |
| ownerId | Владелец |

Отклоняется, если строка уже в реестре или входит в служебный список: `popular`, `feed`, `messages`, `rating`, `bookmarks`, `search`, `about`, `write`, `admin`, `api`, `auth`, `t`, `p`, `u`. При отказе прежний адрес владельца остаётся. Пустой адрес профиля реестр не занимает.

## Тема

| Поле | Правило |
| --- | --- |
| id | Ключ |
| title | Заголовок, обязателен |
| description | До 500 символов |
| avatarUrl | Аватар |
| coverUrl | Обложка |
| slug | Обязательный короткий адрес в общем реестре |
| status | `active` или `archived` |
| position | Порядок в левой карточке |

Активная тема видна в левой карточке и в выборе редактора. Архивная исчезает оттуда. Уже опубликованные в ней статьи остаются по своим адресам и в профиле автора. Новую или редактируемую статью в архивную тему поставить нельзя, пока статус снова не `active`.

## Статья

| Поле | Правило |
| --- | --- |
| id | Ключ |
| authorId | Автор |
| topicId | Ровно одна тема |
| title | От 1 до 150 символов |
| slug | Короткий адрес в общем реестре. Меняется только когда автор меняет его сам |
| blocks | JSON блоков. Схема — [contracts/content.md](./contracts/content.md) |
| visibility | `public`, `members` или `author` |
| commentsEnabled | Комментарии приняты или нет. По умолчанию да |
| status | `draft`, `published`, `hidden` или `deleted` |
| publishedAt | Пусто у черновика. У опубликованной — момент первой публикации |
| reactionCount | Число текущих реакций. Копия, пишет транзакция реакции в `discussion` |
| commentCount | Число комментариев, которые ещё занимают место в обсуждении. Копия |
| viewCount | Число засчитанных просмотров. Копия |
| bookmarkCount | Число людей, у которых закладка сейчас стоит. Копия |
| excerpt | Текстовый фрагмент для карточки, из первых текстовых блоков |
| firstImageUrl | Первое изображение документа или пусто |
| searchVector | Вектор заголовка и текста блоков |

Состояния:

- `draft` → `published`, только если есть заголовок, активная тема и хотя бы один содержательный блок. Один разделитель таким блоком не является. Содержательный блок — абзац или заголовок с текстом, список, цитата, выноска, код, изображение, внешнее медиа, таблица, вложение или карточка человека.
- `published` → `published` при правке. Адрес тот же, пока автор не сменил короткий адрес.
- `published` → `hidden` → `published` действием модератора. Скрытую видит автор с пометкой и администратор в модерации.
- `draft`, `published` или `hidden` → `deleted`. Адрес сообщает, что материал недоступен. Из ленты, поиска, тем, закладок и профилей статья пропадает.
- Черновик не попадает в ленту, поиск, тему, закладки и чужой профиль.

Доступ:

| visibility | Кто читает текст |
| --- | --- |
| public | Гость и участник |
| members | Вошедший участник. Гость видит предложение войти, не текст |
| author | Автор и администратор. Остальные видят недоступность |

Комментарии, реакции, закладки и просмотры доступны только тому, кто может читать статью.

## Комментарий

| Поле | Правило |
| --- | --- |
| id | Ключ |
| articleId | Статья |
| authorId | Автор |
| parentId | Пусто у корня. Иначе комментарий, на который отвечают |
| body | До 5000 символов. Пусто у заглушки удалённого или скрытого |
| status | `visible`, `deleted` или `hidden` |
| editedAt | Пусто, пока автор не правил. Иначе комментарий помечается изменённым |
| reactionCount | Число текущих реакций |
| createdAt | Время |

Состояния:

- Новый комментарий принимается только если зритель вошёл, не ограничен, статью читать можно и `commentsEnabled` истина. Иначе отказ, форма скрыта при выключенных комментариях. Уже написанные комментарии остаются тем, кто статью читает.
- Автор может исправить `visible`. `editedAt` заполняется.
- Удаление автором ставит `deleted`. Если ответов нет, комментарий уходит из списков. Если ответы есть, они остаются, на месте исходного — заглушка «удалён».
- Модератор ставит `hidden` и может вернуть в `visible`. С ответами остаётся заглушка «скрыт». Скрытый комментарий не попадает в правую карточку и в строку под карточкой ленты.
- Ответ ссылается на исходный комментарий и после заглушки не переносится.

Популярные комментарии правой карточки — до 10 `visible` комментариев доступных зрителю статей по убыванию `reactionCount`. Самый обсуждаемый комментарий для строки под карточкой ленты — `visible` комментарий этой статьи с наибольшим числом ответов и реакций.

## Реакция

| Поле | Правило |
| --- | --- |
| userId | Участник |
| targetType | `article` или `comment` |
| targetId | Объект |
| kind | `laugh`, `heart`, `thumb` или `fire` |
| createdAt | Время |

Пара участник–объект одна. Другой `kind` заменяет прежний. Повтор того же `kind` удаляет строку. После записи число на объекте равно числу строк, и в том же outbox уходят `discussion.article_counters.updated` и `discussion.reputation.updated`. Две одновременные реакции разных людей дают две строки.

На экране видны только виды с ненулевым числом и кнопка добавления. Гость и ограниченный строку не создают. Реакция на чужую статью создаёт уведомление автору; реакция на комментарий и своя реакция — нет.

## Просмотр

| Поле | Правило |
| --- | --- |
| articleId | Статья |
| viewerKey | `user:{id}` или `guest:{cookie}` |
| countedAt | Момент последнего засчитанного просмотра |

Пара статья–зритель одна. Если `countedAt` старше 30 минут, счётчик статьи увеличивается на один и время обновляется. Иначе ничего не меняется. Автор и просмотр из модерации строку не пишут.

Просмотр для счётчика — открытие страницы статьи. Раскрытие карточки в ленте этот счётчик не увеличивает; оно кормит Просмотренное в ленте.

## Просмотренное в ленте

| Поле | Правило |
| --- | --- |
| viewerKey | Участник или устройство гостя, тот же ключ, что у Просмотра |
| feedKey | `fresh`, `popular`, `mine` или `topic:{id}` |
| articleId | Статья |
| seenAt | Когда открыл страницу или нажал «Показать полностью» |

Пара зритель–лента–статья одна. Такие карточки в этой ленте стоят за полосой «Скрыто N просмотренных поста». Нажатие на текст полосы показывает их. Крестик не удаляет строки: он только прячет полосу до конца сессии браузера. Следующий визит полосу показывает снова, карточки остаются за ней. Если строк нет, полосы нет.

## Закладка

| Поле | Правило |
| --- | --- |
| userId | Кто сохранил |
| articleId | Статья, которую ему можно читать |
| createdAt | Время |

Пара одна. Повтор снимает закладку. Число на карточке равно числу строк этой статьи. Список человека — `/bookmarks`, те же карточки в центре. Статью, которую читать нельзя, заложить нельзя; скрытая или удалённая статья из чужих закладок пропадает.

## Подписка

| Поле | Правило |
| --- | --- |
| followerId | Кто подписался |
| targetType | `user` или `topic` |
| targetId | Автор или тема |
| createdAt | Время |

Пара подписчик–цель одна. Подписка на себя не создаётся и кнопкой не предлагается. Повторное нажатие удаляет строку. Числа «N подписчиков» и «N подписок» на профиле — числа этих строк. Списки открываются `/u/{slug}/followers` и `/u/{slug}/following`. «Моя лента» — новые видимые статьи авторов и тем из строк зрителя.

## Продвижение

| Поле | Правило |
| --- | --- |
| articleId | Одна строка на статью |
| confirmedAt | Момент последнего подтверждения |
| until | `confirmedAt` плюс 7 суток |

Повторное подтверждение заменяет оба поля. Остаток прошлого срока не прибавляется. Пока `until` в будущем, статья дополнительно входит в «Популярное». Деньги не списываются, платёжной строки нет.

## Репутация и знаки

Репутация не хранится отдельной таблицей: это число текущих строк Реакции на опубликованные статьи и `visible` комментарии человека. `discussion` пересчитывает его в транзакции реакции и публикует `discussion.reputation.updated`; `content` держит копию на профиле. На профиле и в рейтинге показывается не меньше нуля. Положительное — с плюсом, ноль — `0`. Рейтинг `/rating` сортирует участников по этому числу по убыванию.

Знаки не хранятся. Считаются на чтении профиля в `content`.

| Знак | Когда есть |
| --- | --- |
| Первый пост | Есть хотя бы одна опубликованная статья |
| 10 реакций | Репутация не меньше 10 |
| Год на площадке | С `createdAt` участника прошёл год |

На экране только полученные, одним рядом. Нет знаков — ряд скрыт.

## Уведомление

| Поле | Правило |
| --- | --- |
| id | Ключ |
| userId | Получатель |
| kind | `comment`, `reply`, `reaction`, `message` или `moderation` |
| articleId | Статья, если сигнал о ней |
| commentId | Комментарий, если сигнал ведёт к нему |
| conversationId | Диалог, если сигнал о сообщении |
| readAt | Пусто, пока не прочитано |
| createdAt | Время |

Создаётся, когда другой человек комментирует статью получателя, отвечает на его комментарий, ставит реакцию его статье, пишет ему личное сообщение или модератор действует над его материалом. Своё действие уведомления не создаёт. Реакция на комментарий уведомления не создаёт. Непрочитанное открывает связанный материал. Пока человек на сайте, новое уведомление приходит без перезагрузки.

## Диалог и сообщение

Диалог — пара участников. Пара неупорядоченная и одна.

| Поле | Правило |
| --- | --- |
| id | Ключ диалога |
| userLowId | Меньший идентификатор пары |
| userHighId | Больший идентификатор пары |
| lastMessageAt | Время последнего сообщения |

| Поле | Правило |
| --- | --- |
| id | Ключ сообщения |
| conversationId | Диалог |
| senderId | Отправитель, один из пары |
| body | От 1 до 4000 символов, только текст |
| createdAt | Время |
| readAt | Пусто, пока получатель не открыл диалог |

Оба участника вошли и не ограничены. Гость диалогов не видит. Новое сообщение видно в открытом диалоге без перезагрузки. Пока диалог не открыт, у «Сообщений» есть признак непрочитанного.

## Настройки площадки

Одна строка.

| Поле | Правило |
| --- | --- |

Язык меняет надписи интерфейса со следующей страницы и не меняет тексты людей. Нет перевода ключа — русский текст.

## Файл

| Поле | Правило |
| --- | --- |
| id | Ключ |
| uploaderId | Кто загрузил |
| kind | `image` или `attachment` |
| mime | Допустимый тип |

Изображение: JPEG, PNG, WebP, GIF, не больше 8 МБ. Вложение: PDF, DOC, DOCX, TXT, не больше 20 МБ. Иной тип или размер отклоняется, прежний файл в документе остаётся.

## Режим ленты

Не хранится. Считается из адреса.

| Режим | Адрес | Кто в центре |
| --- | --- | --- |
| fresh | `/` | Видимые опубликованные статьи от новых к старым. Это открытие сайта |
| popular | `/popular` | Видимые статьи за последние 7 суток плюс статьи с не истёкшим продвижением, по убыванию суммы реакций и комментариев |
| mine | `/feed` | Новые видимые статьи авторов и тем, на которые зритель подписан. Без подписок — объяснение и переход в «Популярное». Гость — просьба войти |
| topic | `/t/{slug}` | Видимые статьи этой темы от новых к старым |

Порция — около 20 статей, следующая не сбрасывает уже показанные.

## Снимки центра

Не отдельные таблицы — состав ответов `gateway` для центра.

### Карточка ленты

| Поле | Правило |
| --- | --- |
| author | Аватар, имя, ссылка на профиль |
| topic | Тема и ссылка |
| time | Сегодня — часы и минуты, иначе день.месяц.год |
| subscribe | «Подписаться» или «Вы подписаны» у чужого автора. У своего нет |
| menu | Чужая: копировать ссылку, пожаловаться. Своя: редактировать, удалить |
| title | Открывает `/p/{slug}` |
| excerpt | Начало текста |
| image | Первое изображение или отсутствие. Пустой рамки нет |
| expanded | Остаток документа в этой карточке. Кнопка меняется на «Свернуть» |
| reactions | Ненулевые виды и кнопка добавления |
| actions | Число комментариев, закладка и её число, «поделиться», справа просмотры |
| commentPeek | Один самый обсуждаемый видимый комментарий: маленький аватар и начало. Нет комментариев — строки нет |

Число от 1000 сжимается до одной десятой и буквы языка интерфейса.

### Страница статьи

Снимок `/p/{slug}`.

| Поле | Правило |
| --- | --- |
| headerBack | Возврат и усечённое название в центре шапки |
| reach | Полоса охвата только у автора |
| byline | Аватар, имя, тема, время, меню. У чужого — подписка |
| body | Все блоки по порядку, без «Показать полностью». Изображения скруглены |
| reactions | Поставленные виды и «поделиться» справа |
| discussion | Комментарии и форма, если комментировать можно |

Тема статьи подсвечена в левой карточке, если она ещё в списке.

### Карточка профиля

Верхняя карточка центра на своём и чужом профиле.

| Поле | Правило |
| --- | --- |
| cover | Обложка или серая плашка. «Добавить обложку» только у владельца без обложки |
| avatar | Круглый аватар поверх нижнего края обложки, кольцо цвета фона страницы |
| actions | У владельца: «Редактировать», статистика, настройки. У другого человека: «Подписаться» или «Вы подписаны» |
| name | Имя. У владельца рядом круглая кнопка «плюс», которая объясняет репутацию |
| reputation | Зелёное число. Плюс у положительного, `0` у нуля |
| year | «с ГГГГ» из `createdAt` |
| description | Описание, если оно есть |
| counts | Подписчики и подписки |
| badges | Только полученные знаки |
| tabs | «Посты» и «Комментарии». По умолчанию «Посты», синее подчёркивание |

### Карточка списка профиля

Нижняя карточка центра. Стоит под сортировкой «Свежее» / «Популярное». Сортировка между двумя карточками видна.

| Поле | Правило |
| --- | --- |
| sort | «Свежее» или «Популярное» для выбранной вкладки |
| reach | Полоса охвата только у владельца и только внутри этой карточки, над первым постом. Полоса не заменяет боковые карточки |
| items | Посты или комментарии выбранной вкладки, которые зрителю можно читать. Комментарий — фрагмент, название статьи, дата |

Нет постов или комментариев — вкладка объясняет пустоту, без сломанной картинки.

## Каркас раздела

Один на все дочерние маршруты layout-маршрута. Не хранится на сервере.

| Поле | Смысл |
| --- | --- |
| header | Шапка на всю ширину. Слева логотип, по центру пилюля / поиск / возврат, справа поиск, колокольчик, «Написать», аватар |
| left | Левая карточка навигации. На ширине от 1200px всегда в сетке. Ниже — та же карточка в одной панели |
| center | Сменяемый раздел. Единственное место, которое меняет переход |
| right | Правая карточка «Популярные комментарии». На ширине от 1200px всегда в сетке, в том числе пустая. Ниже 1200px — под содержимым центра |

Связи: каркас содержит ровно один текущий раздел. Панель поверх раздела каркас не заменяет.

### Раздел

Вид центра. Подсветка считается из вида, а не хранится отдельно.

| Вид | Что в центре | Подсветка слева |
| --- | --- | --- |
| Лента «Свежее», «Популярное» или «Моя лента» | Список этого режима | Этот режим |
| Тема | Статьи темы | Эта тема |
| Статья | Статья | Тема этой статьи |
| Свой или чужой профиль | Карточка профиля и карточка списка | Нет |
| Сообщения | Переписка или просьба войти | «Сообщения» |
| Рейтинг | Список участников | «Рейтинг» |
| Закладки, поиск, «О проекте», редактор, подписчики, подписки, модерация, темы площадки, настройки площадки | Содержимое этого раздела | Нет |

Правила:

- Прямой адрес задаёт вид сразу, без памяти о прошлом разделе.
- Архивная тема, которой нет в левом списке, никого не подсвечивает.
- Роль меняет инструменты в центре администрирования и не меняет вид каркаса.
- Гость в закрытом разделе видит просьбу войти в центре. Вид каркаса тот же.

### Запись левой карточки

| Поле | Смысл |
| --- | --- |
| kind | `popular`, `fresh`, `mine`, `messages`, `rating` или `topic` |
| topic_id | Только у темы |
| label | Надпись пункта |
| href | Адрес из таблицы разделов |
| is_selected | Результат функции подсветки |
| has_unread | Синяя точка «есть новое» у «Свежего» или «Моей ленты»; признак непрочитанного у «Сообщений». Не заменяет подложку выбранного пункта |

Список тем — только активные темы (`GET /v1/topics`). Длинный список прокручивается внутри карточки; «Показать все» / «Свернуть» раскрывает остальные темы.

### Запись правой карточки

До десяти комментариев, которые этот зритель может читать, по убыванию реакций (`GET /v1/comments/popular`; имя автора и название статьи `discussion` держит денормализованными по событиям). Тот же список на каждом разделе.

| Поле | Смысл |
| --- | --- |
| id | Комментарий |
| author_name | Имя автора |
| author_avatar_url | Аватар или отсутствие |
| article_title | Усечённое название статьи |
| excerpt | Фрагмент комментария |
| reaction_count | Число реакций |
| href | Статья у этого комментария |

Пустой список — отдельное состояние карточки, не отсутствие карточки.

### Состояние оболочки

| is_back_to_top_visible | Истина, когда `center_scroll_top` больше нуля. Производное; потребители читают только этот булев срез |

## Тестовые данные (seed)

Не сущность площадки, а правила того, как её таблицы заполняются в `local` и `dev` (FR-127–FR-131). Описание команд — [seed.md](./contracts/seed.md).

### Идентификаторы и время

| Поле | Правило |
| --- | --- |
| id записи seed | UUIDv5 в фиксированном пространстве имён от ключа `<сущность>:<ключ>` (`user:superadmin`, `article:small:017`, `comment:large:03412`). Один и тот же id в базе владельца и во всех копиях |
| Ключ записей малого набора | Смысловой (`user:author_a`, `article:draft_author_only`), чтобы тесты и `mock-google` ссылались на запись по имени |
| Ключ записей большого набора | Порядковый (`article:large:0001`), порядок задан PRNG с зерном |
| Короткий адрес | Префикс `seed-` (`seed-author-a`, `seed-topic-design`), чтобы не занимать адреса людей |
| `anchor_at` | Начало суток UTC первого запуска или значение `--anchor`. Хранится в `seed_runs`; повторный запуск берёт записанное |
| Время записей | `anchor_at` минус фиксированное смещение (создано, опубликовано, прочитано); не зависит от момента запуска |

### Таблица `seed_runs`

| Поле | Правило |
| --- | --- |
| profile | `small` или `large` |
| anchor_at | Якорь времени, общий для сервиса |
| started_at, finished_at | `finished_at` пусто, если запуск прервался; следующий запуск доделывает недостающее |

В каждой базе якорь один: попытка запустить `large` с другим `--anchor` после `small` отклоняется, пока таблицы не очищены.

### Что и где создаётся

| Сущность | База владельца | Что кладёт seed в чужие базы |
| --- | --- | --- |
| Участник | `identity` | В `content`, `discussion`, `messaging` — копии `role`, `can_publish`, `is_restricted`, `created_at` |
| Профиль, Тема, Статья, Занятый адрес, Подписка, Продвижение, Жалоба, Настройки площадки | `content` | В `discussion`, `messaging`, `notification` — копии имени, аватара, `visibility`, `status`, `comments_enabled`, `author_id`, `title`, `slug` |
| Комментарий, Реакция, Просмотр, Закладка, Просмотренное в ленте, Репутация | `discussion` | В `content` — `reaction_count`, `comment_count`, `view_count`, `bookmark_count` статьи и `reputation` профиля, рассчитанные из тех же записей |
| Диалог, Сообщение | `messaging` | — |
| Уведомление | `notification` | — |
| Файл | `media` | Адреса картинок в блоках статей и в аватарах — строки с фиксированными именами объектов; сами байты загружаются в MinIO |

Сессий и `outbox` seed не создаёт; сессию создаёт вход через `mock-google`.

### Покрытие малого набора

Каждая строка — минимальное требование FR-130 и SC-028. Тест `seed-coverage` обходит эту таблицу и проверяет, что по каждому значению есть хотя бы одна запись во всех базах, где она имеет смысл.

| Сущность | Что должно быть представлено |
| --- | --- |
| Участник | Роли `member`, `admin`, `superadmin`; без права публикации; ограниченный; созданный более года назад; новый без материалов |
| Профиль | С короткими адресами и без (только публичный номер); с обложкой и без; с описанием и без |
| Тема | Активная (не меньше трёх), архивная |
| Статья | Состояния `draft`, `published`, `hidden`, `deleted`; доступ `public`, `members`, `author`; комментарии включены и выключены; с изображением и без; с вложением; длинная (для «Показать полностью») и короткая |
| Комментарий | Корневой, с ответами, ответ, удалённый с ответами (заглушка), скрытый модератором, правленый |
| Реакция | Все четыре вида на статье и на комментарии; у одного участника не больше одной реакции на объект |
| Просмотр, просмотренное в ленте | Есть у читателя и у гостя (по ключу устройства); по каждому режиму ленты |
| Закладка, Подписка | Подписка на автора и на тему; закладки на статьи разных авторов |
| Продвижение | Действующее и истёкшее |
| Репутация и знаки | Все три знака у разных участников; нулевая репутация |
| Жалоба | Не меньше одной на опубликованную статью |
| Уведомление | Прочитанное и непрочитанное, по каждому из видов: комментарий, ответ, реакция, сообщение, модерация |
| Диалог и сообщение | Диалог с прочитанными и с непрочитанными сообщениями |
| Настройки площадки | Название, логотип, язык, текст «О проекте», регистрация, право публикации новым участникам |

### Большой набор

Надмножество малого: не меньше 500 опубликованных статей с доступом `public`, распределённых по темам и авторам; не меньше 3000 комментариев, около трети из них — ответы; реакции на значительную долю статей и комментариев; закладки и просмотренное в пропорции к статьям. Состав задаётся PRNG с зерном, поэтому каждый запуск даёт тот же результат.

### Правила seed

- Пишет только в базу своего сервиса. Событий в брокер не публикует.
- Идемпотентен: повторный запуск не создаёт дубли и не меняет данные, созданные не seed. Строка, уже существующая под тем же id, пропускается; конфликт по уникальному полю с чужой строкой пропускается с предупреждением.
- Запрещён при `APP_ENV=prod` в оркестраторе и в каждом сервисе, до любого изменения данных.
- Счётчики, репутация и копии полей считаются из тех же записей, что и сами записи, поэтому после seed пересчёт владельцем даёт то же значение.
