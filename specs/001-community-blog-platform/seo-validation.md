# Проверка SEO и социальных превью — 2026-10-11

Реализация сохраняет Vite/React. Content вычисляет PageSeo, gateway выдаёт HTML роботам, React заменяет метаданные при переходах. Настройки доступны суперадминистратору, поля SEO статьи — автору. Миграции content/media совместимы с существующими данными; массовой генерации исторических статей нет.

## Проверено

- Content unit: 182 проверки, включая матрицу маршрутов, приватность, canonical, Unicode и связанный JSON-LD.
- Gateway: 65 проверок, включая VK/Telegram/Google, общие маршруты, 404/503, robots/sitemap без User-Agent, экранирование JSON-LD и nonce CSP.
- Web unit: 112 проверок, включая запоздавшие ответы другого маршрута, возврат назад и отсутствие повторяющихся тегов.
- Contracts: 29 проверок; добавлены фикстуры обоих событий социальных обложек.
- Content PostgreSQL: финальные 33 проверки прошли. Проверены версия обложки, дубли, устаревшие результаты, скрытие и восстановление, переименование автора без массовой генерации, обновление общей карточки, повторный запрос давно неготовой карточки, sitemap и фактические даты, SEO через API и права автора.
- Media PostgreSQL/NATS/MinIO: полный цикл доставки запроса, реальный worker, три JPEG в объектном хранилище и обратное событие; дубли, аренда после перезапуска, пять попыток при ошибке хранилища. Финальный прогон вместе с серверным предпросмотром: шесть проверок прошли. Дополнительный прогон двух сценариев подтвердил повторную постановку завершившейся ошибкой задачи и отклонение результата со старой арендой.
- Серверный предпросмотр отдельно проверен через настоящий worker: гостю и ограниченному участнику отказано; текущие цвета формы применяются, JPEG 1074×480 возвращается без записи файла.
- Playwright: все шесть SEO-сценариев прошли в wide-dark, wide-light и narrow-dark: теги, canonical, переходы назад, сохранение SEO черновика/сайта, три предпросмотра. Существующий сценарий редактора прошёл при повторном запуске.
- Метаданные обновляются после изменения профиля, модерации статьи и событий SSE об изменении статьи/настроек; после восстановления соединения текущий SEO-ответ запрашивается заново.
- Визуально проверены OG/Twitter 1200×630 и VK 1074×480, длинный заголовок, кириллица/сербские буквы, светлый фон, прозрачный логотип, заливка и повреждённые исходники. Исправлены переносы и расположение автора/логотипа.
- Сборка всех пакетов/сервисов и typecheck изменённых компонентов проходят. Изменённый код проходит ESLint; `git diff --check` чистый.
- Docker-образ media собирается со шрифтами и отдельным worker. Проверено исполнение worker внутри Node.js 22 и получение JPEG нужного размера.

## Ограничения общей проверки

Общий `pnpm lint` выявляет прежние non-null assertions в `apps/web/tests/e2e/auth.spec.ts` и `services/identity-service/test/integration/auth.spec.ts`, а также предупреждение в сгенерированных иконках. Общий `pnpm typecheck` останавливается на отсутствии деклараций pg во временном адаптере `services/discussion-service/test/comment-db.setup.ts`. Эти файлы не менялись в рамках SEO.

Промежуточные контейнерные прогоны задерживались на создании/остановке Docker-контейнеров. После восстановления Docker финальные проверки изменённых модулей прошли; при повторе использовались два Vitest worker и явная очистка контейнеров. Сервисы и реальные данные площадки не перезапускались; временные тестовые контейнеры удалены. Для чистого окружения:

```sh
pnpm --filter content-service test
pnpm --filter media-service test
pnpm --filter gateway-service test
pnpm --filter web test:unit
pnpm --filter web exec playwright test tests/e2e/seo.spec.ts
```

## После выкладки

Применить штатные миграции content/media и обновить оба сервиса вместе с gateway/web. Внешний вход prod находится вне репозитория: требования к маршрутизации обновлены в README и contracts/environments.md. Проверить через него robots.txt/sitemap и HTML публичных страниц с User-Agent Googlebot, TelegramBot и vkShare. Отдельно проверить 404/503 и отсутствие текста закрытой статьи.

Публичные статьи и профили проверить в Rich Results Test, `/sitemap.xml` отправить в Search Console. Эти проверки требуют развёрнутого публичного адреса и доступа к Search Console, поэтому в локальном запуске не выполнялись.
