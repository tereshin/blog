# Tasks: Платформа публикаций и обсуждений

**Input**: Design documents from `/specs/001-community-blog-platform/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/ (14 файлов, включая environments.md и seed.md), quickstart.md

**Tests**: Спецификация не требует TDD. Тесты включены там, где их явно называет plan.md (раздел Testing): unit для чистых функций (подсветка, форматирование, отбор «Популярного», одна реакция на объект, репутация, срок продвижения), integration через testcontainers (доступ, адреса, публикация, окно просмотра, идемпотентность потребителей), контрактные фикстуры событий, Storybook на каждое состояние карточек, Playwright по путям quickstart.md. Тесты окружений и тестовых данных (`pnpm test:infra`) называет plan.md отдельно: seed не запускается в `prod`, повтор seed не меняет данные, покрытие малого seed, состав `prod` без `mock-google`. Тесты идут после реализации внутри фазы истории, не first.

**Organization**: Задачи сгруппированы по пользовательским историям spec.md (US1–US16). Фазы 1–2 — общая инфраструктура, без которой ни одна история не запускается. Требования к окружениям и тестовым данным (FR-123–FR-132, SC-026–SC-028) не относятся ни к одной истории: каркас `infra/` — в фазе 1, тестовые данные и вход через `mock-google` для трёх первых сервисов — в фазе 2, остальное — в разделе «Окружения и тестовые данные» фазы 19.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Можно выполнять параллельно (другие файлы, нет зависимости от незавершённых задач)
- **[Story]**: К какой истории относится задача (US1…US16)
- Каждая задача называет точные пути файлов

## Path Conventions

Монорепо pnpm workspaces по plan.md:

- Всё, что запускает окружение, — в `infra/`: `infra/compose/`, `infra/env/`, `infra/docker/`, `infra/mock-google/`, `infra/scripts/`. В корне репозитория и в `docker/` нет ни `docker-compose.yml`, ни Dockerfile (FR-123)
- Клиент: `apps/web/src/{app,pages,widgets,features,entities,shared}`, тесты `apps/web/tests/{unit,e2e}`
- Сервисы: `services/<name>-service/src/{main.ts,app.ts,config/env.ts,modules/<entity>/<entity>.{routes,controller,service,repository,events,schema,types,errors}.ts,infra/{db,broker,http}}`, тесты `services/<name>-service/test/{unit,integration,contract}`
- Пакеты: `packages/{contracts,logger,config,errors,telemetry,broker,http-kit,seed-data}` — только инфраструктура, контракты и детерминированные данные seed, без бизнес-логики и без доступа к БД
- Точки входа одноразовых задач сервиса с базой: `src/migrate.ts` (`node dist/migrate.js`), `src/seed.ts` (`node dist/seed.js --profile small|large`), `src/bootstrap.ts` у `identity` и `content`; логика seed — `src/seed/{seed.ts,bootstrap.ts}`
- Поля JSON, query и колонки — `snake_case`; маршруты `/v1/<ресурсы>`; события `<context>.<entity>.<past-tense>` с версией в имени файла `*.v1.ts`

### Within Each User Story

- Контракты (`packages/contracts`) → сервис-владелец (schema → repository → service → routes/consumer) → клиент (`entities/api` → `features`/`widgets` → `pages` → маршрут) → живые сигналы → e2e
- Тесты сервиса — после реализации модуля, в той же фазе
- Story и state-компоненты — вместе с компонентом

### Parallel Opportunities

- Phase 1: все `[P]` (линтинг, `packages/*`, `infra/compose`, `infra/env`, `infra/docker`, `infra/scripts`, `packages/seed-data`, `apps/web`) параллельно после T001

## Notes

- `[P]` — разные файлы и нет зависимости от незавершённых задач той же фазы
- Каждая история проверяется своим критерием из раздела «Independent Test» и своим `e2e`-файлом
- `packages/broker` и `packages/http-kit` добавлены к списку пакетов plan.md как инфраструктурные (без бизнес-логики) — они убирают шесть копий outbox-воркера, health-маршрутов и проверки служебного контекста
- Поля данных и ограничения (длины, перечисления, окна времени) взяты из data-model.md и контрактов дословно; при расхождении кода и этих документов правится код
- Всё, что запускает окружение, лежит в `infra/` (FR-123); в `prod` нет `mock-google`, seed и обходного входа, а состав ограничен списком FR-126
- `packages/seed-data` — данные, а не правила: детерминированные генераторы без доступа к БД; правила видимости и подсчёта остаются у сервисов, согласованность проверяет тест
- Коммит после каждой задачи или логической группы; остановка на любом чекпоинте даёт проверяемый инкремент
