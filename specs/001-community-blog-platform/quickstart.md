# Quickstart: Платформа публикаций и обсуждений

Проверка, что правила площадки держатся от входа до модерации, что один каркас стоит на каждом разделе и что лента, статья и профиль совпадают с образцами по составу и поведению.

Контракты: доступ — [access.md](./contracts/access.md), статья и файлы — [content.md](./contracts/content.md), обсуждение — [discussion.md](./contracts/discussion.md), поиск и переписка — [discovery.md](./contracts/discovery.md), модерация — [admin.md](./contracts/admin.md), события — [realtime.md](./contracts/realtime.md), зоны каркаса — [shell.md](./contracts/shell.md), адреса и подсветка — [sections.md](./contracts/sections.md), лента — [feed.md](./contracts/feed.md), страница статьи — [article.md](./contracts/article.md), профиль — [profile.md](./contracts/profile.md), жесты — [actions.md](./contracts/actions.md). Поля — [data-model.md](./data-model.md).

Полный набор тестового кода здесь не приводится. Его место — реализация и `tasks.md`.

## Предусловия

- Node.js 22, pnpm, Docker с Compose v2. Всё остальное (PostgreSQL 16 ×6, NATS JetStream, MinIO, сервисы, клиент, `mock-google`) поднимает окружение `local` из `infra/` одной командой — [environments.md](./contracts/environments.md)
- Файл `infra/env/local.env` создан из `local.env.example`; секретов в репозитории нет, `CHANGE_ME` в `local` допустим. Отсутствие обязательной переменной роняет сервис на старте
- Учёток Google для проверки не нужно: вход в `local` и `dev` идёт через `mock-google`, участники берутся из seed ([seed.md](./contracts/seed.md)): суперадминистратор, администратор, автор с правом публикации и публичными постами с изображением и комментарием, читатель, без права публикации, ограниченный, новый
- Малый seed уже задаёт: регистрация открыта, язык русский, две активные темы и одна архивная, длинная статья и профиль выше окна, свой профиль автора без обложки (`newcomer`), длинный список тем — после большого seed
- Для сценариев 13 и 17 — большой seed (500+ публичных статей)
- Широкое окно 1280px в тёмном виде, если сценарий не говорит иначе. Узкое — 390px. Граница из спецификации — 1200px
- Клиент `apps/web` можно запускать и локально против `gateway` из Compose; до готовности сервисов — против фикстурного `gateway` (MSW) с тем же контрактом

## Запуск

```bash
pnpm install
cp infra/env/local.env.example infra/env/local.env
pnpm local                                  # infra:up local + infra:seed local small: сервисы, базы, NATS, MinIO, клиент, mock-google, малый seed
```

Открыть `http://localhost:8080` (клиент). `gateway` — `http://localhost:3000`, `mock-google` — `http://mock-google.localhost:8081`. `GET /health/ready` на порту каждого сервиса отвечает `200`, когда его база и брокер доступны. На «Войти» открывается страница `mock-google` со списком участников seed.

Отдельные шаги и режимы:

```bash
pnpm infra:up local                         # только окружение, без данных
pnpm infra:seed local small                 # малый набор (идемпотентен: повтор ничего не добавляет)
pnpm infra:seed local large                 # + 500+ статей и тысячи комментариев
pnpm infra:down local -- --volumes          # остановить и очистить тома
pnpm --filter web dev                       # http://localhost:5173 с горячей перезагрузкой, проксирует /v1 на gateway; VITE_API_MOCK=1 включает фикстурный gateway
pnpm --filter <service> dev                 # один сервис с хоста; переменные из infra/env/local.host.env
```

Правила доступа, идемпотентность потребителей, состояния компонентов и сквозные пути:

```bash
pnpm -r test                 # Vitest: unit + integration (testcontainers) во всех сервисах; unit клиента: подсветка, форматирование, отбор «Популярного», реакции, репутация, срок продвижения
pnpm -r test:contract        # фикстуры событий и схем /v1 из packages/contracts с обеих сторон
pnpm --filter web storybook  # состояния карточки ленты, карточек профиля, ряда реакций, левой и правой карточек: данные / пусто / загрузка / ошибка
pnpm --filter web test:e2e   # Playwright против окружения local (E2E_TARGET=local, малый seed, вход через mock-google), на 1280px и 390px, в тёмном и светлом виде
pnpm test:infra              # окружения и seed: seed в prod падает до записи, повтор seed не меняет данные, покрытие малого seed, состав prod без mock-google
```

Ожидаемый итог всех команд — успех. Сквозной прогон покрывает сценарии ниже, а не заменяет ручной просмотр образцов.

## 1. Гость на главной

1. Выйти из учётки, если вход есть.
2. Открыть `/` на 1280px в тёмном виде.
3. Нажать «Показать полностью» на длинной карточке. Открыть заголовок статьи.

Ожидание: шапка, левая карточка, карточки ленты от новых к старым, справа «Популярные комментарии». У чужой карточки сверху аватар, имя, тема, время и «Подписаться», ниже заголовок, фрагмент, изображение, «Показать полностью», реакции и ряд действий. В центре шапки пилюля с названием первой статьи «Популярного», не поле поиска. Прокрутка ленты оставляет шапку и обе карточки. «Показать полностью» дописывает остаток в ту же карточку, надпись «Свернуть», адрес не меняется. Заголовок открывает `/p/{slug}`. Черновиков и чужих закрытых статей нет. Пустая площадка объясняет, что статей нет, боковые карточки остаются.

## 2. Все разделы в одном каркасе

С главной по очереди открыть адреса из таблицы разделов: `/popular`, `/feed`, `/t/{slug}`, `/p/{slug}`, `/u/{slug}`, `/messages`, `/rating`, `/bookmarks`, `/search`, `/about`, `/write`, списки подписчиков и подписок, затем под администратором `/admin/moderation`, `/admin/topics`, `/admin/settings`.

Ожидание на каждом адресе при 1280px: шапка, левая карточка и правая карточка на месте. Инструменты раздела в центре. Подсветка совпадает с таблицей разделов: на профиле, в закладках, поиске, «О проекте», редакторе, списках и администрировании не подсвечены ни режим ленты, ни тема, ни «Сообщения», ни «Рейтинг». Прямая загрузка `/u/{slug}` и `/p/{slug}` без захода с главной показывает обе карточки сразу.

Повторить открытие главной и профиля при пустом ответе `GET /v1/comments/popular`. Ожидание: правая карточка видна, текст объясняет пустоту, центр не стал шире на место карточки.

## 3. Режимы ленты

Нажать «Популярное», «Свежее», тему и «Показать все». Гостем нажать «Моя лента».

Ожидание: меняется центр, выбранный пункт получает подложку, шапка и обе карточки остаются. «Показать все» становится «Свернуть» и раскрывает темы в левой карточке. На странице темы над списком подписка на тему. «Моя лента» без подписок объясняет, откуда она берётся, и предлагает «Популярное». Гость на «Моей ленте» видит просьбу войти.

## 4. Статья и возврат

Открыть статью из ленты. Нажать возврат. Открыть статью прямой ссылкой в новой вкладке и нажать возврат.

Ожидание: в шапке возврат и усечённое название, слева подсвечена тема, текст и изображения целиком, без «Показать полностью». Под текстом поставленные реакции и «поделиться», ниже обсуждение. Возврат из ленты попадает в ту же ленту на то же место. Возврат с прямой ссылки открывает «Свежее» с начала.

Под автором на его статье видна полоса охвата и «Купить показы». Под читателем этой полосы нет. Панель до подтверждения говорит, что деньги не списываются. После подтверждения статья есть в «Популярном». Повторное подтверждение отсчитывает новые 7 суток от этого нажатия.

## 5. Вход и профиль

1. Войти новой учёткой Google.
2. Сохранить имя, описание и короткий адрес.
3. Открыть этот адрес в другом сеансе без этой учётки.
4. Выйти через меню аватара.

Ожидание: учётка создана, чужой сеанс видит имя и только разрешённые статьи. Адрес без короткого имени строится из публичного номера. После выхода сайт показывает гостя. Занятый или служебный короткий адрес не сохраняется, прежний остаётся, причина видна.

Повторить первый вход при закрытой регистрации другой новой почтой. Ожидание: учётка не создана, есть объяснение. Уже созданный автор по-прежнему входит.

## 6. Профиль между колонками

Открыть свой профиль без обложки и чужой профиль.

Ожидание: на обоих профилях видны шапка, левая карточка и «Популярные комментарии»; содержимое профиля только в центре. У своего — две центральные карточки: серая плашка с «Добавить обложку», аватар поверх неё, «Редактировать», статистика, настройки, репутация, «с ГГГГ», вкладка «Посты» с синим подчёркиванием; между карточками сортировка «Свежее»; в карточке списка полоса охвата над постом. У чужого — «Подписаться» и нет «Редактировать», «Добавить обложку» и «Купить показы». Вкладка «Комментарии» показывает фрагмент, название статьи и дату. На своём имени «плюс» объясняет репутацию и не подписывает на себя; на чужом имени «плюса» нет. Репутация `0` без плюса, положительная с плюсом. Числа подписчиков открывают список людей в том же каркасе. `/rating` показывает участников по убыванию репутации и подсвечивает «Рейтинг».

## 7. Черновик и публикация

Под автором с правом публикации и одной активной темой:

1. Открыть «Написать».
2. Собрать заголовок, абзац, список, изображение и таблицу.
3. Сохранить черновик и открыть ленту гостем.
4. Опубликовать.
5. Сменить заголовок, не трогая адрес.
6. Начать правку, не сохранить и попытаться уйти.

Ожидание: редактор даёт блоки из контракта статьи. Гость черновик не находит ни в ленте, ни в поиске, ни в теме, ни в профиле. После публикации материал есть у тех, кому его можно читать. Адрес тот же. Статья без содержательного блока, с одним разделителем, не публикуется. Предупреждение об уходе лежит поверх каркаса, колонки на месте; отказ оставляет редактор.

Гость и участник без права публикации по «Написать» получают вход или объяснение, черновик не создаётся.

## 8. Два сеанса на одной статье

Открыть публичную статью автором и вторым участником. Не перезагружать страницы.

1. Второй отправляет комментарий.
2. Оба ставят реакцию одного вида, первый снимает свою повторным нажатием, второй меняет вид.
3. Автор правит текст, пока у второго в форме набран несохранённый ответ.
4. Обновить страницу вторым участником сразу ещё раз.

Ожидание: комментарий, числа и новый текст видны во втором сеансе в течение 2 секунд. Несохранённый ответ не пропал. Повторное открытие в пределах 30 минут не добавляет второй просмотр. Авторский заход просмотр не добавляет. Две одновременные реакции разных людей обе учтены, повтор одного человека число не удваивает, другой вид заменяет прежний. Реакция на статью даёт автору уведомление, реакция на комментарий — нет.

## 9. Реакция, подписка, закладка, полоса

Читателем на чужой карточке:

1. Нажать «Подписаться» дважды.
2. Сохранить закладку и открыть её из меню аватара.
3. «Поделиться».
4. Развернуть две статьи ленты, уйти и вернуться на эту ленту. Нажать текст полосы, затем крестик.
5. Гостем попробовать реакцию, подписку и закладку.

Ожидание: кнопка подписки становится «Вы подписаны» и возвращается обратно. Закладка открывается списком карточек в обычном каркасе, число на карточке совпадает. «Поделиться» копирует адрес и показывает подтверждение. Над лентой «Скрыто 2 просмотренных поста»; текст полосы показывает их, крестик убирает только полосу до следующего визита. Гость получает вход, действие не выполняется.

## 10. Кто не видит текст

1. Опубликовать статью «только вошедшим» и открыть её гостем.
2. Поставить «только мне» и открыть вторым участником.
3. Выключить комментарии и отправить комментарий запросом, не через форму.

Ожидание: гость видит предложение войти и не видит текст; шапка и боковые карточки остаются. Второй участник на «только мне» текста не видит, автор и администратор видят. Комментарий при выключенной форме не сохраняется, старые комментарии остаются. В поиске, правой карточке и закладках этих закрытых текстов нет.

## 11. Поиск, уведомление, сообщение

1. Нажать поиск в шапке, найти публичную статью по слову из заголовка, закрыть поиск.
2. Вторым участником прокомментировать статью автора, пока автор на сайте.
3. Отправить личное сообщение и открыть его во втором сеансе, не обновляя страницу.
4. Не открывая диалог, остаться на другой странице.

Ожидание: поле открывается в центре шапки вместо пилюли и возвращает её после закрытия; результаты — в `/search` в том же каркасе; статья есть среди результатов, которые ищущему можно читать. У автора точка на колокольчике, панель открывается под ним, переход открывает статью у комментария. Сообщение появляется в открытом диалоге. У «Сообщений» есть признак, пока диалог не открыт. Гость по «Сообщениям» видит просьбу войти.

Своя реакция и свой комментарий автору уведомление не создают.

## 12. Модерация и язык

1. Суперадминистратором загрузить логотип, сменить язык на английский, сохранить «О проекте», завести вторую тему.
2. Назначить второго участника администратором.
3. Администратором скрыть опубликованную статью.
4. Читателем пожаловаться на чужую статью из меню «…».
5. Ограничить автора и попытаться от его имени прокомментировать.

Ожидание: следующая страница показывает английские надписи, текст статьи тот же, числа сжимаются с `K`/`M`. Логотип слева в шапке. «О проекте» из меню аватара открывает сохранённый текст в центре. Тема есть в левой карточке. Администратор скрывает материал и не сохраняет язык. Скрытой статьи нет в ленте гостя, у автора она с пометкой, на уже открытой ленте она пропадает в течение 2 секунд. Жалоба видна в модерации вместе со статьёй. Ограниченный видит объяснение, действие не проходит; его вторая открытая вкладка при следующем действии тоже получает отказ. Архив темы убирает её из выбора новой статьи и оставляет старые адреса.

## 13. Прокрутка, длинная лента и отказ действия

1. На 1280px открыть длинный профиль и длинную статью, прокрутить центр до конца, нажать кнопку внизу слева.
2. На главной прокрутить темы внутри левой карточки.
3. На фикстуре из 500+ статей прокрутить «Свежее» до конца, затем открыть статью и вернуться.
4. Сделать так, чтобы `POST /v1/reactions` отвечал ошибкой, и поставить реакцию.

Ожидание: шапка и обе карточки остаются; центр возвращается к началу одним нажатием; в покое кнопки возврата нет. Прокрутка тем двигает левую карточку и не уносит шапку. Лента без рывков, порции подгружаются до того, как лента кончилась, возврат попадает на то же место. Реакция появляется сразу, через мгновение возвращается в прежнее состояние и видна причина.

## 14. Светлый вид, узкое окно и клавиатура

1. В меню аватара включить светлый вид. Открыть главную, статью и свой профиль.
2. Сузить окно до 390px и открыть те же три адреса. Со статьи перейти в `/messages`, `/rating` и `/about`. На профиле расширить окно за 1200px и снова сузить.
3. На 390px открыть панель навигации с клавиатуры (Tab до кнопки шапки, Enter), нажать Escape.
4. На 1280px пройти главную только клавиатурой: Tab до карточки, Enter на «Показать полностью», Tab до ряда реакций, Enter, Tab до «Подписаться», Enter; открыть меню аватара, уведомления и диалог «Купить показы», закрыть Escape.

Ожидание: порядок блоков тот же; фон светлый, карточки белые, «Купить показы» и активная вкладка синие. На узкой ширине одна колонка, левая навигация открывается одной и той же кнопкой на всех разделах, популярные комментарии под центром, у «Написать» перо без слова, «Редактировать», статистика и настройки под именем. На 1200px и шире колонки снова рядом, в том числе у профиля и сообщений. Пока панель открыта, Tab ходит только внутри неё; после Escape фокус возвращается на кнопку, которая её открыла. Каждый шаг выполним с клавиатуры, фокус виден, читалка экрана называет кнопки. Возврат гостя на это устройство и участника в учётку сохраняет вид.

## 15. Панели, загрузка центра и отказ одного источника

1. На 1280px открыть уведомления и закрыть их. На своей статье открыть статистику и закрыть её.
2. Замедлить ответ центра и перейти из статьи в профиль.
3. Сделать так, чтобы `GET /v1/comments/popular` отвечал ошибкой, а `GET /v1/topics` — нормально. Открыть главную и профиль. Починить ответ и нажать «Повторить».

Ожидание: после закрытия панели тот же раздел и обе карточки. На время ожидания видна заготовка центра; левая и правая карточки не исчезают и не оставляют пустую полосу. Левая карточка с темами на месте, правая показывает ошибку с «Повторить» внутри себя; центр и шапка не затронуты; «Повторить» заполняет карточку без перезагрузки.

## 16. Сессия, обрыв и отказ сервиса

1. Войти автором в двух вкладках. В первой начать комментарий и не отправлять. Во второй выйти. Вернуться в первую и нажать «Отправить».
2. Открыть публичную статью двумя участниками. У второго отключить сеть на 20 секунд, пока первый комментирует. Включить сеть.
3. Остановить `messaging-service`. Открыть ленту, статью и «Сообщения».
4. Вставить адрес публичной статьи и адрес черновика в проверку превью (например, `curl -A Telegrambot`).

Ожидание: в первой вкладке поверх статьи появляется панель входа, набранный текст на месте; после входа комментарий отправляется. У второго участника после включения сети комментарий первого появляется в течение 5 секунд без перезагрузки. Лента и статья работают, «Сообщения» показывают ошибку с «Повторить» в центре, каркас на месте. Превью публичной статьи содержит заголовок, описание и картинку; превью черновика не содержит ничего из его содержимого.

## 17. Окружение local и тестовые данные

1. На чистой машине с Docker выполнить `pnpm local`. Засечь время до готового сайта.
2. Открыть `http://localhost:8080`, нажать «Войти» и по очереди войти под суперадминистратором, администратором, автором, читателем, участником без права публикации, ограниченным и новым.
3. Выполнить `pnpm infra:seed local small` повторно. Сравнить число строк во всех шести базах до и после.
4. Выполнить `pnpm infra:seed local large`. Открыть `/` гостем.

Ожидание: сайт работает не позже чем за 10 минут после одной команды (SC-026). На странице входа виден список участников seed, и любой из них входит тем же путём, что и настоящий Google: другого эндпоинта у `identity-service` нет. Лента, темы, комментарии, сообщения и уведомления заполнены; видны статьи в состояниях «опубликована», «скрыта» (у автора и модератора) и «черновик» (только у автора), доступ «всем», «вошедшим» и «автору», действующее и истёкшее продвижение, все четыре реакции, три знака, прочитанные и непрочитанные уведомления и сообщения. Повторный запуск малого seed не меняет число строк ни в одной базе (SC-027). После большого seed первая порция главной появляется не позже чем за 2 секунды, лента из 500+ карточек прокручивается без рывков (SC-021, SC-028), а малый набор остался на тех же идентификаторах.

## 18. Prod: нет seed и нет тестового входа

1. С `infra/env/prod.env` на заглушках выполнить `pnpm infra:up prod`.
2. С реальным `prod.env` выполнить `pnpm infra:seed prod small`. Сразу после — число строк в базах.
3. Выполнить `docker compose -f infra/compose/docker-compose.yml -f infra/compose/docker-compose.prod.yml config --services`.
4. Выполнить `pnpm infra:bootstrap-prod` дважды.
5. Запустить `identity-service` с `APP_ENV=prod` и `GOOGLE_ISSUER_URL`, указывающим на `mock-google`.

Ожидание: на заглушках окружение не стартует и называет первую заглушку. Seed завершается ошибкой, не запустив ни одного контейнера; число строк в базах прежнее (SC-027, FR-128). В списке сервисов нет `mock-google` и ничего сверх состава из [environments.md](./contracts/environments.md). После `bootstrap-prod` есть суперадминистратор из `SUPERADMIN_EMAIL` без `google_sub` и настройки по умолчанию, но нет тестовых людей, тем, статей и комментариев; второй запуск ничего не дублирует. Вход этой почтой через Google привязывает `sub` к уже созданной строке. `identity-service` с чужим издателем в `prod` не стартует.
