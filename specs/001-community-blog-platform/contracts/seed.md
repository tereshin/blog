# Contract: Тестовые данные

Команды seed и prod-минимума, профили объёма и гарантии. Реализует FR-127–FR-131 и SC-026–SC-028. Что именно создаётся и как идентифицируется — [data-model.md](../data-model.md#тестовые-данные-seed). Окружения и команды запуска — [environments.md](./environments.md).

## Команды

| Команда | Где разрешена | Результат |
| --- | --- | --- |
| `pnpm infra:seed <env> small` | `local`, `dev` | Малый набор: несколько десятков записей, каждая сущность и каждое состояние из FR-130 |
| `pnpm infra:seed <env> large` | `local`, `dev` | Малый набор плюс 500+ опубликованных статей и тысячи комментариев (FR-131) |
| `pnpm infra:seed <env> <profile> -- --anchor=2026-01-01T00:00:00Z` | `local`, `dev` | То же, с якорем времени, заданным явно (тесты и CI) |
| `pnpm infra:bootstrap-prod` | любая, обязательна в `prod` | Суперадминистратор и настройки по умолчанию, без людей и материалов |
| `pnpm local` | `local` | `infra:up local` и `infra:seed local small` |

Одноразовый запуск одного сервиса: `docker compose … run --rm <service> node dist/seed.js --profile small|large`.

## Порядок и границы

Оркестратор `infra/scripts/seed.ts` запускает одноразовые контейнеры по очереди: `identity`, `content`, `discussion`, `messaging`, `notification`, `media`. Каждый пишет только в свою базу. Между сервисами нет вызовов: ссылки согласованы общими детерминированными идентификаторами из `packages/seed-data` (автор статьи, комментатор, получатель уведомления существуют в базе своего сервиса).

## Гарантии

| Гарантия | Как проверяется |
| --- | --- |
| В `prod` seed завершается ошибкой до любого изменения (FR-128) | Оркестратор читает `APP_ENV` и выходит с кодом ≠ 0, не запустив контейнеров. Каждый `seed.ts` проверяет `APP_ENV` до открытия соединения на запись. Тест: в `prod` после запуска `seed_runs` пуст и число строк не изменилось (SC-027) |
| Идемпотентность (FR-129) | Запуск дважды подряд не увеличивает число строк ни в одной таблице ни одной базы и не меняет значений. Тест сравнивает хеш содержимого таблиц до и после |
| Не трогает чужие данные | Строки, созданные не seed, не обновляются и не удаляются; конфликт по короткому адресу с такой строкой пропускает запись и пишет предупреждение |
| Детерминированность | При одном `--anchor` и профиле два запуска на пустых базах дают побайтно одинаковые таблицы (кроме служебных `started_at`, `finished_at`) |
| `large` — надмножество `small` | Id малого набора остаются теми же; запуск `large` после `small` только добавляет |
| Согласованность копий | После seed счётчики статей, репутация и копии полей совпадают с пересчётом владельцем |
| Покрытие (SC-028) | Тест `seed-coverage` обходит таблицу «Покрытие малого набора» из [data-model.md](../data-model.md) и находит запись по каждому значению |
| Быстрая лента после `large` (SC-021) | Первая порция главной появляется не позже чем за 2 секунды |

## Участники seed и вход

Малый набор содержит участников с фиксированными `sub` и почтой; те же значения читает `mock-google` ([environments.md](./environments.md#вход-через-mock-google)).

| Ключ | Роль и состояние | Для чего |
| --- | --- | --- |
| `superadmin` | `superadmin`; совпадает с `SUPERADMIN_EMAIL` окружения `local` | Темы, язык, оформление, настройки площадки, регистрация |
| `admin` | `admin` | Модерация; отказ в настройках площадки |
| `author_a` | `member`, `can_publish`, статьи во всех состояниях, знак «Год на площадке» | Основной автор |
| `author_b` | `member`, `can_publish`, 10+ реакций | Знак «10 реакций», второй автор |
| `reader` | `member`, без статей, подписан на авторов и темы | Лента «Моя», закладки, сообщения |
| `no_publish` | `member`, `can_publish = false` | Объяснение вместо редактора |
| `restricted` | Ограничен | Отказы с объяснением |
| `newcomer` | Недавно появился, без материалов | Профиль без знаков, репутация `0` |

## Prod-минимум

`pnpm infra:bootstrap-prod` повторяемо (без дублей) делает два шага через use case сервисов, не через SQL в обход:

1. `identity-service`: если нет участника с `email = SUPERADMIN_EMAIL`, создаёт его с `role = superadmin`, `google_sub = null`, публикует `identity.user.created` через outbox. Профиль создаст `content-service` по событию.
2. `content-service`: если нет строки настроек площадки, создаёт настройки по умолчанию (название, язык `ru`, регистрация закрыта, право публикации новым участникам по умолчанию).

Первый вход Google с подтверждённой (`email_verified`) назначенной почтой привязывает `sub` к этой строке ([access.md](./access.md)). Тестовых людей, тем, статей и комментариев команда не создаёт.

## Ошибки

| Ситуация | Результат |
| --- | --- |
| `prod` | Код ≠ 0, текст объясняет, что seed в `prod` запрещён; ничего не запущено и не записано |
| Один из сервисов упал на пачке | Прежние пачки сохранены, `finished_at` пусто; следующий запуск доделывает недостающее |
| `large` с другим якорем после `small` | Отказ с объяснением; чтобы сменить якорь, нужно очистить тома |
| Нет `SUPERADMIN_EMAIL` для `bootstrap-prod` | Сервис `identity` не стартует и команда завершается с ошибкой |
