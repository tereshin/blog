# Quickstart Validation: Простые страницы

Это сценарии проверки **после реализации**. Сейчас созданы только документы;
page API, миграция и перечисленные новые тесты ещё не реализованы.

## Подготовка

Из корня репозитория, Node.js ≥ 22, pnpm 9.15, Docker с Compose.
Использовать существующие local env по README/`infra/env/*.example`.
Секреты не копировать в план или VITE-переменные.

```sh
pnpm install --frozen-lockfile
pnpm infra:up local
pnpm infra:seed local small
```

Новая миграция content должна быть включена в обычный процесс запуска
окружения. Входить через существующий Firebase Auth emulator под
суперадминистратором из малого seed. Для отрицательных проверок — admin,
member и restricted. Обходной login endpoint не создавать.

UI local — существующий PUBLIC_ORIGIN. Для Playwright он должен совпадать
с WEB_ORIGIN gateway; при необходимости задаётся E2E_BASE_URL.
Для повторов и конфликтов использовать тестовый клиент с обычными
cookie/CSRF; токены не помещать в URL и не печатать в консоль.

## 1. Создание и публикация — US1, SC-001–SC-003

1. Открыть `/admin`, затем «Страницы». В чистой базе — пустое состояние.
2. «Создать страницу» → new. Название «Контакты», slug `contacts`.
3. Добавить paragraph/list/image через Editor.js, сохранить черновик.
4. Убедиться: статус draft, один ID, первый ответ version=1; редактор
   остаётся смонтированным. Выйти в список и открыть сохранённую строку.
5. Проверить title, slug, порядок/данные блоков; в гостевой вкладке
   `/pages/contacts` — «Страница не найдена».
6. «Опубликовать». В гостевой вкладке открыть страницу заново: title/blocks
   видны, shell присутствует; нет статьи в ленте, теме, профиле и поиске статей.
7. Повторить roundtrip всех остальных типов блоков из общего contracts/blocks.
8. Публикация пустого документа и только delimiter отклоняется без смены статуса.

## 2. Правки и предпросмотр — US2, SC-002/SC-004

1. Открыть published в редакторе, изменить текст и открыть preview.
2. Preview показывает новые правки, гостевая ссылка до save показывает старую
   версию; dirty не сброшен. Вернуться — позиция/текст сохранились.
3. Проверить предупреждение о немедленном обновлении, сохранить.
4. Гость открывает ссылку заново — новый текст; published не позволяет
   поменять slug. Снятая с публикации страница тоже не позволяет менять его.
5. Попытаться сохранить published с пустым содержанием — отказ;
   прежний публичный текст остаётся. status=draft с пустым документом допустим.

## 3. Снятие и удаление — US3, SC-004

1. Снять с публикации: следующий public GET — 404, admin GET сохраняет блоки.
2. Опубликовать повторно — прежний URL, published_at первой публикации сохранён.
3. Открыть удаление, отменить — без изменений. Подтвердить — 204,
   исчезновение из списка, admin detail/public GET дают 404.
4. Создание с тем же slug получает page_slug_taken. Никакого удаления
   бинарных файлов вместе со страницей нет.

## 4. Права и отсутствие утечки — FR-011/FR-016, SC-003

Гость не получает admin данные; member и admin — 403, операций в БД нет.
Superadmin с can_publish=false может управлять страницами; restricted
и неподтверждённая почта не могут. Проверить это API, не только скрытием кнопок.
Повтор ранее успешного ключа после утраты роли тоже не отдаёт admin ответ.

После снятия/удаления проверить public API, `/v1/seo?path=/pages/contacts`,
prerender gateway с bot user-agent и sitemap: нет блоков/title закрытой
страницы. Public missing/draft/deleted одинаковы. В local/dev индексация
выключена; sitemap включённого prod проверяется интеграционным тестом
с APP_ENV=prod и отдельной тестовой БД, без запуска prod seed.

## 5. Ошибки и конкурентность — FR-014/FR-015, SC-005

- Задержать ответ записи, продолжить ввод. После успеха поздние правки
  остаются dirty; повторное сохранение фиксирует их отдельной версией.
- Потерять ответ успешного POST и повторить тот же key/payload:
  тот же ID/ответ, одна запись и одно событие, в том числе после рестарта.
- Отправить другой payload с тем же key — 409, без изменений.
- Повторить успешный PATCH и DELETE — без повторного version/outbox.
- Открыть один ID в двух сессиях superadmin: после записи первой вторая
  получает 409, её текст сохраняется. Просмотр серверной версии не стирает
  локальную; отказаться от своих правок можно только явно.
- Network error и 503 media не помечают текст сохранённым. 401 открывает
  вход поверх редактора; после входа набранный текст остаётся и сохраняется.
- Уход с dirty: «Остаться» оставляет форму; «Уйти без сохранения» уходит.
  Закрытие/перезагрузка показывает beforeunload.
- Ошибка инициализации Editor.js: Save/publish выключены, повтор доступен.
  Переходы между existing ID не смешивают документы.

## 6. Общий документ и медиаполитика — FR-013

Проверить локальный preview и сохранённую страницу с HTML в paragraph,
caption цитаты, list и table: исполняемый код/обработчики не выполняются.
Недопустимые URI и embed origin не попадают в DOM. Сервер отвергает
неизвестный блок, >500 блоков, вложенность >10 и body >1 MiB.

Суперадминистратор A размещает свой файл, B сохраняет другую правку страницы
с этим файлом — успех. B пытается добавить файл A, отсутствующий в текущей
странице, — отказ. После удаления URL из сохранённого документа B не может
добавить его обратно как доверенный старый файл. Проверить ложный prefix
origin (`trusted.example.evil`) и границы пути. Статья сохраняет прежний
запрет чужих файлов. Media отказ не оставляет частичной записи/outbox.

## 7. Оболочка и производительность — SC-006

Проверить 390/1024/1280px, обе темы: direct new/edit/public ссылки,
неизменный shell при переходах, правильный возврат, отсутствие подсветки
темы у simple page, локальный overflow таблиц. Список из 500 страниц
загружается порциями без blocks; после 100 строк виртуализируется.
В отчёте сборки Editor.js отсутствует в initial chunk.

## Автоматические проверки после реализации

Файлы page/pages ниже — запланированные тесты, а не существующие команды
с уже реализованными проверками. Vitest integration запускает PostgreSQL
существующим testing helper; требуется Docker. Для событий дополнительно
проверяется outbox→broker по принятому контрактному/integration harness.

```sh
pnpm lint
pnpm typecheck
pnpm --filter @blog/contracts test
pnpm --filter content-service test:unit
pnpm --filter content-service test:contract
pnpm --filter content-service exec vitest run test/integration/page.spec.ts test/integration/prerender.spec.ts test/integration/article-write.spec.ts test/integration/slug.test.ts
pnpm --filter gateway-service test
pnpm --filter web test:unit
pnpm --filter web test:e2e tests/e2e/admin-pages.spec.ts tests/e2e/pages.spec.ts tests/e2e/editor.spec.ts
E2E_TARGET=local pnpm --filter web test:e2e tests/e2e/admin-pages.spec.ts tests/e2e/pages.spec.ts
pnpm --filter web build-storybook
pnpm build
pnpm --filter web size
```

E2E с mock API проверяет состояния; E2E_TARGET=local — реальные границы
gateway/content/identity/media. Изменения общего renderer/editor также
проверяются существующими тестами редактора статьи и stories.

Приёмка завершена, когда SC-001–SC-006 выполнены, права и утечки проверены
через API, новые события валидны, общий редактор статей не получил регрессий,
линтер/типизация/сборка и бюджет бандла проходят.
