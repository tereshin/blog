# UI Contract: Страницы

## Маршруты и доступ

| URL | Slice | Доступ и переход |
| --- | --- | --- |
| `/admin/pages` | pages/admin-pages | superadmin; каталог → список |
| `/admin/pages/new` | pages/admin-page-new | superadmin; новая форма, без записи до Save |
| `/admin/pages/:id` | pages/admin-page-edit | superadmin; существующая страница по UUID |
| `/pages/:slug` | pages/simple-page | published для всех, включая гостя |

Все маршруты — дети ShellLayout, страницы lazy. Список имеет ADMIN_ROUTES.pages,
parent=home, role=superadmin. Динамические new/:id регистрируются явно;
getAdminRoute/родитель шапки понимают их и возвращают `/admin/pages`.
Возврат списка ведёт `/admin`. Публичная страница использует возврат из
обычной оболочки, с прямой ссылки — на «Свежее».

`RequireRole` закрывает первоначальный доступ. Модель уже открытого редактора
остаётся смонтированной при сессионном 401; кнопки управления выключаются,
вход показывается поверх центра. Прямой посетитель без роли не видит редактор
и не запускает загрузку административных данных. Повторный вход проверяет роль.

## Список

В главном каталоге админки — строка «Страницы» с иконкой документа и пояснением
«Информационные страницы сайта». Список использует существующие Card/DataTable/
Select/Button и принятые в админке размеры полей.

Колонки: название-ссылка, короткий адрес, статус, дата изменения, действия.
Фильтр: «Все / Черновики / Опубликованные», синхронизирован с query status.
Порции по 20; cursor сбрасывается при изменении фильтра. После 100 загруженных
строк применяется виртуализация. Документы блоков в список не загружаются.
Кнопка «Создать страницу» открывает new. Для published есть «Открыть страницу»;
для draft публичная ссылка не обещает доступность.

Состояния: skeleton, пусто («Страниц пока нет» + создание), пустой фильтр,
ошибка с повтором, нормальный список, загрузка следующей порции.

## Редактор

Название — существующий TitleTool Editor.js, отдельное поле slug имеет
постоянный префикс `/pages/`. Перед первым сохранением slug вводится явно;
автогенерация адреса не требуется в MVP. Под slug показываются допустимый
формат, ошибка занятости и будущая публичная ссылка. После первой публикации
slug readonly с текстом «Адрес закреплён после публикации».

Редактор использует те же инструменты и загрузку файлов, что статьи.
На странице нет выбора темы/автора/видимости, переключателя комментариев,
социальных счётчиков или панели публикации статьи.

| Состояние | Основные действия |
| --- | --- |
| Новая несохранённая | «Сохранить черновик», «Предпросмотр», возврат |
| Сохранённый draft | «Сохранить черновик», «Опубликовать», «Предпросмотр», «Удалить» |
| published | «Сохранить изменения», «Предпросмотр», «Открыть страницу», «Снять с публикации», «Удалить» |
| Запись / загрузка файла | Мутации выключены; ввод остаётся доступным |
| Редактор ещё не готов | Save/publish/preview выключены, осмысленный skeleton |
| Сессия истекла | Текст сохранён в памяти, мутации выключены, панель входа |

После первой успешной записи new получает ID/version в форме, остаётся
на прежнем маршруте и не перемонтирует Editor.js. Кнопка публикации появляется
после сохранения. Ссылка из списка ведёт на canonical admin edit по ID.
До первой записи статус подписан «Новый черновик», после — «Черновик».

Published имеет заметный текст: «Сохранение сразу обновит страницу для
посетителей». Снятие с публикации выполняет PATCH status=draft и может
сохранить текущие правки в том же запросе. Публикация отправляет текущие
поля и блоки атомарно. Удаление требует диалога с названием страницы,
кнопками «Отмена»/«Удалить», затем возвращает к списку.

## Снимок, dirty и повторы

Ввести в существующий widgets/editor публичный контракт чтения снимка и
подтверждения успешного сохранения. Снимок содержит title из TitleTool,
нормализованные blocks и revision; заголовок и блоки берутся из одного
вывода Editor.js, не из несогласованных асинхронных значений React state.
Slug и revision метаданных фиксируются при начале операции. Подтверждение
касается только отправленного снимка. Правки во время запроса остаются dirty.

Preview читает снимок без подтверждения. Кнопка показывается после ready;
ошибку сохранения Editor.js нельзя подменить пустым документом. При успешном
ответе не пересоздавать редактор из query.data; если сервер изменил inline
разметку, очищенный результат — подтверждённая база, локальные новые правки
сохраняются. Поведение поздних onChange и нормализации подтверждается тестами.

Одна активная мутация на форму. Retry сетевой операции использует тот же
ключ и зафиксированный payload; новые изменения после неё отправляются
отдельной операцией с новой версией. При 409 текст остаётся в редакторе;
показываются «Просмотреть сохранённую версию» и «Перезагрузить и отказаться
от моих правок». Второе требует явного подтверждения. Тихого overwrite нет.

При уходе с dirty — Dialog «Есть несохранённые изменения», «Остаться» /
«Уйти без сохранения». При закрытии вкладки — штатное beforeunload.
Ни документ, ни title/slug не записываются в browser storage.

## Предпросмотр и публичное отображение

Preview — переключение внутри того же редактора, без отдельного URL
и без размонтирования экземпляра. Он показывает текущий title и общий
BlockRenderer; возврат оставляет позицию и текст редактора.

Общий renderer принимает нейтральные блоки из нижнего слоя, не ArticleModel.
Все inline-поля, включая caption цитаты, очищаются DOMPurify. Embed URL
проверяются по провайдеру и origin/пути. Внешние ссылки получают
noopener/noreferrer. Неизвестные блоки не превращаются в сырой HTML.

Public page — один h1 и блоки, без автора, даты статьи и обсуждений.
Состояния: loading, page, одинаковый not-found для missing/draft/deleted,
error/retry для проблем сервера. При refetch 404 прежний текст исчезает.
Обновления уже открытой вкладки через SSE не обещаются в MVP.

## Доступность и проверки

Подписи, фокус, диалоги и таблицы — через существующий shared/ui/HeroUI.
Ошибки полей связаны с контролами, status записи имеет aria-live.
На телефоне таблица/блоки имеют локальную прокрутку, окно не расширяется.
Проверить светлую/тёмную темы и интерфейс ru/en/sr.

Stories: список во всех состояниях, новый/draft/published редактор,
saving/error/conflict/session-expired, preview всех блоков.
Stories общего renderer мигрируют вместе со статьёй.
